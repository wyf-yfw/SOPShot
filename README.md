# SOPShot 原生 macOS 原型

SOPShot 是一个把一组操作截图交给用户自己的多模态模型，最后生成一页操作说明的原生 macOS 工具。它没有自己的模型服务，也不要求维护服务器。

## 当前核心路径

1. 打开软件，先在“模型设置”里选择厂商和视觉模型，填写自己的 API Key。
2. 点击“开始采集”，完成一遍真实的办公操作。SOPShot 不录制视频。
3. 每次鼠标点击或关键键盘按键后，软件在本机直接截取一张屏幕图片，并把这张图片和该操作绑定。普通字母和数字只作为输入记录，不触发截图。
4. 点击“停止采集”，进入截图预览。点击任意缩略图时，左侧显示对应截图，右侧显示这次操作以及附近捕获到的鼠标和键盘操作。
5. 先在预览中检查截图，再点击“开始生成说明”。这一步之前不会调用模型，也不会发送图片。
6. 模型只接收已经确认的操作截图，直接返回标题、适用对象、流程目标、步骤说明和提醒。
7. 用户不需要填写步骤或处理中间结果。只有在最终预览完成后，才可以选择编辑或导出。

## 隐私与数据

- SOPShot 不提供中转服务器，操作截图会从当前电脑直接发送到用户填写的模型接口。
- API Key 会保存到 `~/Library/Application Support/SOPShot/api-keys.json`，不再读写 macOS 钥匙串，因此应用启动时不会因为 API Key 弹出密码授权。目录权限为 `0700`，文件权限为 `0600`。这种方式方便本机使用，但不具备钥匙串的系统级保护；切换到这版后需要重新输入并保存一次 API Key。
- 厂商、模型和接口地址会保存在本机设置中。
- 采集时只在本机临时记录鼠标点击、滚动和键盘动作类别；不记录具体输入文字、剪贴板内容、密码或 API Key，也不会把原始输入事件发送给模型。
- 首次启动会请求“输入监控”权限；如果系统没有再次弹窗，可在“系统设置 > 隐私与安全性 > 输入监控”中打开 SOPShot。截图采集仍需要单独的屏幕录制权限。
- 软件不创建、不保存临时 MP4，也不采集声音。当前窗口只保留本次生成的截图和文字。
- 导出前仍应检查截图中的姓名、邮箱、手机号、账号、订单号和客户资料。

## 运行

使用 Xcode 或 Swift Package Manager 构建后运行 SOPShot。本目录中的 SOPShot.app 是当前构建产物。

首次截图采集时，macOS 可能要求在“系统设置 > 隐私与安全性 > 屏幕录制”中允许 SOPShot。

### 本地开发版

本机开发版使用固定的 `SOPShot Development` 签名身份，不再使用每次构建都会变化的临时签名。日常修改后运行：

```sh
./scripts/build-dev.sh
open SOPShot.app
```

这会重新构建、复制应用包、用同一把本地开发证书签名并验证签名。首次切换到这个开发版时，macOS 可能仍要求在隐私设置中重新允许一次屏幕录制和输入监控；完成这一次后，只要继续使用这个脚本构建，应用的权限识别不会因为普通代码修改而变化。证书私钥只保存在当前用户的登录钥匙串，不会写入项目或上传。

## 当前边界

- 屏幕截图使用 ScreenCaptureKit，当前默认采集主显示器。
- 当前原型以鼠标点击和关键键盘按键作为截图触发器：每次点击、空格、回车、Tab、Esc、删除、方向键、翻页/Home/End、功能键或带修饰键的快捷键，都在本机请求一张截图；普通字母和数字只记录为输入类别，不触发截图，也不记录具体字符。不做视觉相似度去重，也不合并连续的关键操作；用户确认后才交给模型理解。本地不做 OCR，也不替模型判断业务语义。
- 模型必须按约定返回 JSON，并为每一步提供 timestamp 和 frame_index。
- Gemini 和其他厂商的模型名称、接口限制可能随官方平台更新，设置页保留了接口地址以便用户调整。
- 尚未实现自动遮盖姓名、邮箱、手机号和账号。
- 草稿只保留在当前窗口内，刷新应用会丢失。

## 设计读取

- 面向办公交接的原生工具，界面像可整理的工作纸。
- 橙色只用于截图采集和提醒，红色只表示正在采集或危险动作。
- 主工作区使用纸张结构，因为最终产物是一页可交接说明。
- 默认主流程只有“设置模型、采集、确认操作截图、开始整理、最终预览”几个必要动作。
